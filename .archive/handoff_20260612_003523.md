## Why this design (engine constraints — confirmed in code, don't re-investigate)

- One node = one provider. The original is a single dynamic `loop:` node (one provider only) cycling roles via `state.json`. Can't put codex+opus in one loop node.
- DAG is acyclic — `loader.ts:186` rejects cycles ("Cycle detected"). No backward edges, so no real loop across provider-split nodes. => **unroll** into a fixed forward chain.
- `trigger_rule` default `all_success` (`dag-executor.ts:603`) blocks downstream if any upstream skips. Must use **`all_done`** (line 612) on every chained node.
- `when:` is fail-closed; a skipped node emits **empty** output (`dag-executor.ts:3030`) and `when:` can only read `$node.output`, never a file.
- **Therefore the pattern:** before each LLM node, a **bash gate** (always runs, `all_done`) reads `state.json` from disk via python3 and prints exactly `yes`/`no`; the LLM node fires only on `when: "$gate.output == 'yes'"`. True skip-on-pass, survives empty-output trap.
- Role prompts (negotiator/generator/evaluator) reused verbatim from the original; only evaluator PASS transition differs per variant (`→ negotiating` for negotiated, `→ building` for upfront). init-workspace caps `totalSprints` at 8.
